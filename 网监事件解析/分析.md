## 二、网监事件的数据流路径

根据规范，事件数据流遵循 **"自身感知 → 分布采集 → 统一管控"** 三级架构：

```
┌─────────────────────────────────────┐
│         网络安全管理平台 (主站)        │  ← 统一管控、高级分析
│         [DL/T634.5104协议]           │
└─────────────┬───────────────────────┘
              │ 事件上传/远程调阅
┌─────────────▼───────────────────────┐
│      网络安全监测装置 (I型/II型)      │  ← 分布采集、协议转换
│   · I型：高性能，500监测对象，主站侧   │
│   · II型：中等性能，100监测对象，厂站侧 │
└─────────────┬───────────────────────┘
              │ 自定义TCP/SNMP/Syslog
┌─────────────▼───────────────────────┐
│    监测对象（服务器/工作站/网络设备/   │  ← 自身感知
│    数据库/安防设备/电力监控系统）      │
└─────────────────────────────────────┘
```

## 三、关键通信协议与抓包要点

### 1. 装置→监测对象（下行采集）

| 监测对象类型 | 协议 | 端口 | 抓包过滤条件 |
|-------------|------|------|-------------|
| **服务器/工作站** | 自定义TCP协议 | 默认端口需查具体部署 | `tcp` + 目标端口 |
| **数据库** | 消息总线（事件触发） | - | 需解析应用层 |
| **网络设备** | **SNMP v2c/v3**、SNMP TRAP、Syslog | 161/162/514 | `udp.port==161 or udp.port==162 or udp.port==514` |
| **安防设备**（防火墙/IDS/隔离/加密） | **GB/T 31992** 协议 | - | 专用协议，需定制解析 |
| **防病毒** | 事件触发上报 | - | 应用层解析 |

**自定义TCP报文格式**（附件3 表8）：
```
┌────────┬────────┬─────────┬─────────┬────────┬────────┐
│ 报文头  │ 报文类型│ 参数/返回值│ 报文内容长度 │  报文体  │  报文尾  │
│ 0x55   │ 1字节  │  2字节   │  4字节   │  N字节  │ 校验和+0xAA │
└────────┴────────┴─────────┴─────────┴────────┴────────┘
```
- 报文类型定义：`0x01`=采集信息上报, `0x02`=参数查看, `0x03`=参数设置, `0x04`=启动基线核查, `0x05`=启动主动断网

### 2. 装置→管理平台（上行事件上传）

**核心协议：DL/T634.5104（IEC 104）**

| 要素 | 说明 |
|------|------|
| **协议标准** | DL/T 634.5104-2009（等同IEC 60870-5-104） |
| **角色** | 管理平台=服务端，监测装置=客户端 |
| **安全机制** | TCP连接建立后，**基于调度数字证书的双向身份认证** |
| **连接数** | 每个装置只建立**1条TCP连接** |
| **附加** | I型装置还支持通过**消息总线**上传 |

**抓包过滤**：`tcp.port==2404`（IEC 104默认端口）

### 3. 管理平台远程调阅（反向查询）

| 功能 | 协议 | 说明 |
|------|------|------|
| 远程调阅数据 | 基于TCP的自定义协议 | 装置作为服务端，平台作为客户端 |
| 服务代理 | 自定义TCP | 至少支持4个并发连接 |
| 参数配置 | 同上 | 系统参数、通信参数、事件处理参数 |

## 四、实际抓包与解析步骤

### Step 1: 环境准备

```bash
# 1. 确定网络拓扑中的抓包点
#    - 方案A：在监测装置与管理平台之间（镜像交换机端口）
#    - 方案B：在监测装置上直接抓包（tcpdump/Wireshark）
#    - 方案C：在监测对象与装置之间（分析原始采集协议）

# 2. 安装工具
sudo apt-get install tcpdump wireshark tshark
```

### Step 2: 抓包命令示例

```bash
# ===== 场景1：抓取装置→管理平台的IEC 104事件上传 =====
sudo tcpdump -i eth0 -w sgu104.pcap 'tcp port 2404'

# ===== 场景2：抓取装置→网络设备的SNMP采集 =====
sudo tcpdump -i eth0 -w snmp.pcap 'udp port 161 or udp port 162'

# ===== 场景3：抓取装置→服务器的自定义TCP协议 =====
# 假设自定义TCP端口为 9000
sudo tcpdump -i eth0 -w custom_tcp.pcap 'tcp port 9000'

# ===== 场景4：全流量抓取（需过滤） =====
sudo tcpdump -i eth0 -w full.pcap 'host 监测装置IP or host 管理平台IP'
```

### Step 3: Wireshark解析配置

**IEC 104解析**（通常自动识别）：
- 若未自动解析：右键TCP流 → Decode As → 选择IEC 60870-5-104

**自定义协议解析**（需Lua插件或手动分析）：
```lua
-- 示例：国网自定义TCP协议简易解析器（Wireshark Lua）
-- 保存为 ~/.wireshark/plugins/sgu_tcp.lua

sgu_tcp_proto = Proto("SGU_TCP", "State Grid Security Monitor TCP")

local f_header = ProtoField.uint8("sgu.header", "Header", base.HEX)
local f_type = ProtoField.uint8("sgu.type", "Message Type", base.HEX)
local f_param = ProtoField.uint16("sgu.param", "Param/Return", base.HEX)
local f_len = ProtoField.uint32("sgu.length", "Content Length", base.DEC)
local f_checksum = ProtoField.uint8("sgu.checksum", "Checksum", base.HEX)
local f_tail = ProtoField.uint8("sgu.tail", "Tail", base.HEX)

sgu_tcp_proto.fields = {f_header, f_type, f_param, f_len, f_checksum, f_tail}

function sgu_tcp_proto.dissector(buffer, pinfo, tree)
    if buffer:len() < 10 then return end
    if buffer(0,1):uint() ~= 0x55 then return end  -- 不是0x55开头则退出
    
    pinfo.cols.protocol = "SGU_TCP"
    local subtree = tree:add(sgu_tcp_proto, buffer())
    
    subtree:add(f_header, buffer(0,1))
    subtree:add(f_type, buffer(1,1))
    subtree:add(f_param, buffer(2,2))
    subtree:add(f_len, buffer(4,4))
    
    local content_len = buffer(4,4):uint()
    local total_len = 9 + content_len  -- head(1)+type(1)+param(2)+len(4)+body(N)+checksum(1)+tail(1)
    
    if buffer:len() >= total_len then
        -- body
        -- checksum
        subtree:add(f_checksum, buffer(8+content_len, 1))
        subtree:add(f_tail, buffer(9+content_len, 1))
    end
end

-- 注册到特定端口（假设自定义TCP端口为9000）
local tcp_table = DissectorTable.get("tcp.port")
tcp_table:add(9000, sgu_tcp_proto)
```

### Step 4: 事件内容解析（关键）

根据**附件3 附录B《上传事件信息规范》**（第24页起），事件上传包含以下信息类型：

| 信息类别 | 内容说明 | 解析重点 |
|---------|---------|---------|
| **外设接入事件** | USB/串口/并口/光驱插拔 | 设备类型、接入时间、拔出时间 |
| **用户登录事件** | 登录成功/失败 | 用户名、IP、时间、失败原因 |
| **危险操作事件** | 高危命令执行 | 操作类型、命令内容、影响范围 |
| **状态异常事件** | CPU/内存/磁盘/网口异常 | 资源使用率、阈值、持续时间 |
| **安全告警事件** | 入侵/病毒/非法外联 | 告警等级、攻击源、处置建议 |

**IEC 104中的信息对象地址（IOA）映射**：
- 需查阅具体厂商实现或附录C《数据上传通信规范》（第48页起）
- 通常采用** ASDU类型标识**区分事件类别：
  - `0x01` = 单点信息（告警开关量）
  - `0x09` = 测量值（CPU/内存等数值）
  - `0x1E` = 带时标的报文（事件顺序记录）

## 五、从附录提取的具体采集信息点

根据**附件1 附录A**，各设备类型的采集内容如下（抓包时需关注这些字段）：

### A.1 操作系统（服务器/工作站）
| 信息类型 | 采集内容 | 采集频度 | 信息用途 |
|---------|---------|---------|---------|
| 登录信息 | 操作信息、登录成功/失败 | 事件触发 | 行为监视 |
| 运行信息 | CPU/内存利用率、TCP连接数、网口监听、USB插拔、串口/并口/光驱使用 | 周期(1min)或事件触发 | 设备监视、安全告警 |
| 告警事件 | 非法外联、非法操作、权限变更、关键目录变更、软件版本变更 | 事件触发 | 安全告警 |

### A.2 网络设备（交换机）
| 信息类型 | 采集内容 | 备注 |
|---------|---------|------|
| 操作信息 | 用户登录、操作信息、运行时长、CPU/内存、网口状态、MAC合法性 | CPU/内存1分钟平均值，超阈值记录 |
| 网络连接 | IP连接信息 | - |
| 运行信息 | 风扇/电源/温度/端口/电路板故障 | 设备温度过高 |

### A.3 数据库
| 采集内容 | 采集频度 | 备注 |
|---------|---------|------|
| CPU/内存/磁盘/表空间利用率 | 周期(1min~6h) | 超阈值形成告警 |
| 数据库状态/运行时长/连接数 | 周期 | 仅监视，可历史查询 |
| 用户登录失败/锁表/SQL执行异常/计划任务失败 | 事件触发 | 连续失败→重要告警 |

## 七、关键提示

1. **证书加密问题**：管理平台与装置之间的IEC 104连接在**双向证书认证后**才传输事件，若抓包点在认证之后，可直接解析；若需解密前期握手，需拥有调度数字证书私钥（几乎不可能，属于核心安全资产）。

2. **自定义协议端口**：附件未明确规定自定义TCP的端口号，实际部署中需向设备厂商确认或通过网络扫描发现。

3. **SNMP社区字符串**：抓包SNMP时需知道community string（通常为"public"或定制值），否则无法解析MIB内容。

4. **附录C/D/E**：附件3的第48页起包含**规范性附录**，详细定义了通信报文格式、服务代理规范、采集信息与命令控制技术要求，是编写解析器的核心依据。由于PDF部分页面解析失败，建议获取完整规范文本或联系设备厂商获取SDK/开发文档。

如需针对特定协议（如IEC 104或自定义TCP）编写更详细的解析代码，或需要分析具体抓包文件，可以进一步说明。
